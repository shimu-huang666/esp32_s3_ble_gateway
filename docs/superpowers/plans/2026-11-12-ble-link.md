# S3 最小 BLE 网关实施计划

> **For agentic workers:** 按用户已授权的方案在当前会话执行；不重复询问方案确认。使用完成前验证检查实际输出。

**Goal:** 从官方空白项目建立 S3 中央设备，每秒发送 PING 并接收 C3 的 PONG。

**Architecture:** 采用 ESP-IDF 自带 NimBLE。复用 blecent 的扫描、连接、订阅流程，并直接引用 SDK 内的 nimble_central_utils。全部连接状态和定时发送都在 NimBLE 主机事件队列中处理。

**Tech Stack:** ESP-IDF v6.1、ESP32-S3 N16R8、C、NimBLE、clang-format 21。

**Spec:** 当前对话中已确认的最小 BLE 双向通信需求；具体边界见下文。

## Global Constraints

- 与 C3 使用相同的服务 UUID、特征 UUID 和四字节 PING/PONG，不发送字符串结束符。
- 一对一、无配对认证；不接入麦克风、舵机或电源控制；暂不启用 PSRAM。
- 采用 Allman 格式；添加 Agent.md；代码、测试脚本、文档分别提交。
- 建立独立 Git 仓库，从空白 main 建立 codex/minimal-ble-link 功能分支。

## Review Focus

- C3 晚上电：S3 持续扫描，发现后自动连接。
- 连接断开：取消发送定时器、清除发现结果并重新扫描。
- 订阅尚未成功：不得提前发送 PING。
- 收到错误或截断的通知：不得记录为有效 PONG。
- 两块板同时重启：必须先完成服务发现和通知订阅，再开始通信。
